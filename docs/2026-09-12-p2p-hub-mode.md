# P2P Hub 模式:多个 NAT 后的 spoke → 一个 NAT 后的 hub(单 tun 设备)

## 背景(Context)

当前 p2p 隧道是点对点的:udp "数据报通道"只在一侧的 GOST 对自己本地的 p2p host 调
`OpenTunnel(network=udp)` 时才存在,通道把该 local edge 与 per-peer 的流配对。而常见的
真实形态——多人在**纯 NAT 环境**(两端都没有公网 IP:hub 是 NAT 后的公司机器,每个 spoke
也在各自 NAT 后)访问**一个持有一块 tun 设备的 hub**——今天无路可走:hub 从不主动拨号,
因此没有通道,每个 spoke 入站的通道流都被拒绝(`p2p/direct.go:663-685`,即日志里的
"channel stream refused")。

探索中的关键发现:**GOST 的 tun handler server 模式本身就是一个 hub**——
`x/handler/tun/server.go` 的 `handleServer` 在服务地址上绑定一个 UDP socket,把 N 个 UDP
对端解复用到同一块设备(`h.routes: IP → UDPAddr`,由每个 client 的 keepalive
`"GOST"+passphrase+IPs` 注册路由,passphrase 经 handler 的 `auther` 认证)。
**前提:该 tun handler 不得设 `tun.p2p`**(`x/handler/tun/metadata.go:31`)——`h.md.p2p` 为真时
`updateRoute`/`findRouteFor` 把路由 key 压成 `IPv6zero`(单 peer),整个 hub 会塌成一条路由;
那是既有的单 peer 形态,与本计划的 hub 互斥。满足此前提后,要补的**不是** tun handler 重构,
也**不是**插件的入站方向,而是一个很小的 host 侧特性:

> **Hub 模式**:hub 的 p2p host 为每个**在白名单内**的 spoke 公钥维护一条数据报通道,
> 其 **local edge 是 per-spoke 的本地 UDP socket,统一指向配置的 tun server 地址**;
> 该 edge 负责隧道帧(2 字节 BE,一报一帧)↔ 裸 IP 数据报的互转。于是 tun server 把每个
> spoke 当作普通的不同 UDP 客户端——解复用、keepalive 路由注册、passphrase 认证全部原样
> 生效。spoke 侧零改动。

已确认的决策:强制 peer 公钥**白名单**(fail closed);每 spoke 一个本地 UDP socket →
**可重复的 `--target` 目标池**(带 `udp://` scheme,按网络分池、轮询分发——见 §6);范围含
示例配置、e2e、spoke→公司内网路由、spoke↔spoke 互通。

## x 侧 keepalive 修复(探索中发现,共三处,都很小)

**背景**:tun 的"注册 + 保活"全靠 keepalive:client 每次重拨发一条
`"GOST"+passphrase+IPs`;server 逐 IP 认证(`auther.Authenticate(ip, passphrase)`)后
注册 `routes: IP→UDPAddr` 并**回显**一条 20 字节报文;client **仅在收到该回显时**刷新读
deadline(`3×period` 无回显即判死重拨)。实测确认三处缺陷,本期全修:

**D1 — 门控 bug(必修)**:keepalive 只在 `network == "udp"` 时启动
(`x/handler/tun/client.go:47-52`),而 `Handle` 的 `network` 来自
`net.SplitHostPort(raddr)`——p2p 下 `raddr` 是链节点 addr 即 **peer 的 base64 公钥(无冒号)**
(`x/handler/tun/handler.go:92-95`、`x/p2p/tunnel_dialer.go:81`),故恒为 `"ip"`,keepalive
**从不运行**:注册、回显、deadline 全失效,hub 路由表永远为空。
修法(一个 hunk):

```go
// x/handler/tun/client.go:47   (原为: if network == "udp" {)
if network == "udp" || h.md.keepAlivePeriod > 0 {
    iterCtx, iterCancel := context.WithCancel(ctx)
    defer iterCancel()
    go h.keepalive(iterCtx, cc, ips)
}
```

保留 `network == "udp"` 分支不是保守,是必须:`keepalive()` 在 `period<=0` 时**仍无条件发一次**
注册握手(`client.go:77-79`)才提前返回;只按 `keepAlivePeriod > 0` 门控,会让"udp 网络 + 未开
keepalive"的既有配置**连握手都不发**(今天 routes 不过期,那种配置一直可用)。`||` 让该分支
逐位不变,新分支只让 `keepalive: true` 在非 udp 网络(p2p 的 `"ip"`)也生效——今天那里是死配置。

**D3 — 存活只认回显,数据包不续期**(`client.go:176-189`):新 p2p 通道在"对端边暂缺"时按
IP 语义丢弃字节,控制报文同样会被丢;通道一抖,恰好管命的那条回显被吃 → 3×period 后 client
误判死亡、重拨(现场观测到的 ~15s 抖动)。修法:reader 里把 `SetReadDeadline(now+3×period)`
从"仅 keepalive 分支"提到**任何一次成功读取之后**(读到任何字节都是隧道存活的证据)。

**D2 — 服务端路由永不过期**(`server.go:255-269`):routes 只增不删、无 last-seen;离场
spoke 的 IP→addr 永留,设备侧继续向死地址黑洞发送。修法:`routes` 值改为
`struct{ addr net.Addr; lastSeen time.Time }`;`updateRoute` 记录 now;`findRouteFor` 命中
时若 `now-lastSeen > routeTTL` → `Delete` 并视为无路由(惰性过期,无需后台扫描;写路径
每包都查,足够);过期时 Info 记一条(可被 e2e 断言)。
**routeTTL 是 opt-in**:仅当 server 侧配了 `keepalive/ttl`(`h.md.keepAlivePeriod > 0`,
`metadata.go:23-27`)时取 `routeTTL = 3×keepAlivePeriod`;未配置时**不过期**(保持今天的
"routes 只增"语义)。理由:这条落在全项目最常用的 handler 上,若默认过期,任何"udp + 未开
keepalive"的既有部署会在 ~30s 后失联——那是破坏性变更,不该搭 hub 的车。hub 的 server 显式写
`keepalive: true, ttl: 10s` → routeTTL=30s(即 e2e 采用的形状)。

（D4 回显无身份校验、D6 无路由仅 Debug——记录在案,本期不做。）

## 改动 —— p2p host(模块 `github.com/go-gost/p2p`;plugin 仍只放契约)

### 1. `p2p/frame.go`(新)—— 模块内 framing
`writeFrame`/`readFrame`/`maxFrame` 在流迁移时删掉了;hub edge 需要它们回来(host 不能
import `x/p2p/streamconn`)。保持最小且纯函数:

```go
const maxFrame = 65535 // 与 x/p2p/streamconn.MaxFrame 对齐
func appendFrame(dst, p []byte) []byte               // 追加一个带帧头的数据报
func frameAt(b []byte) (payload, total int, ok bool) // 解析头部帧,不完整则 ok=false
```

### 2. `p2p/dgram.go`(新)—— 帧↔数据报适配(中性件,供 hub 与未来 udp --forward 复用)
每个 spoke 一个连到 target 的 `*net.UDPConn`,实现 帧字节流 ↔ 裸 IP 数据报 互转:
- `Write(p)`(由 `serveStream` 喂入):追加到内部 `wbuf`,对每个完整帧发一次
  `UDPConn.Write`(跳过零长帧),保留不完整的尾字节;`wbuf` 上界为
  `maxFrame + 2 + channelChunkSize`(帧头 2 字节),无需额外封顶。
- `Read(p)`(由 `pumpLocal` 调用):先消费已缓冲的帧字节;否则读一个数据报进
  header+payload 暂存缓冲、在头部打上 2 字节前缀,返回帧字节(帧可跨多次 Read,spoke 侧
  conn 会重组)。
- `Local/RemoteAddr`、`Set*Deadline` 委托;`Close` 幂等(`sync.Once`)。
- **有意做成中性的 `dgramEdge`(conn, target)**:hub 通道今天用它;将来 `--forward` 若要
  支持 UDP(本地 udp listener + 同一套帧↔数据报适配),直接复用这一个实现,不再写第二份。
  文件放 `p2p/dgram.go`(与 frame.go 同层),不叫 hub*。

### 3. `p2p/udp.go` —— hub 通道创建
```go
func (e *Engine) addHubChannel(peer derpclient.PublicKey, target string) error
```
解析并 `DialUDP` 目标,`e.openChannel(peer)`(refs=1),`ch.attachLocal(newDgramEdge(c))`。
`loop`/`serveStream`/`pumpLocal`/按公钥排序的角色逻辑**原样复用**——与拨号通道的唯一区别
是 local edge 为启动时一次性挂上的 UDP 适配器。**不做引用计数/release**:hub 通道保留初始
refs=1 到进程结束,由 `Engine.Close` 统一回收(它已遍历 `e.chans` 做 teardown)——与
`--forward` 先例一致;不涉及 `server.tunnels`/`dropTunnel`/`gcPending`。

### 4. `p2p/engine.go` —— hub 状态、目标池与准入
```go
targets   targetPool                      // 按网络分池(§6);TCP 入站与 hub udp 各自取用
hubAllow  map[derpclient.PublicKey]bool   // nil = hub 模式关闭(fail closed)
func (e *Engine) EnableHub(keys []derpclient.PublicKey) error   // udp target 已并入 e.targets
func (e *Engine) hubDenied(peer derpclient.PublicKey) bool
```
`EnableHub` 为每个 key 建通道+edge,每个 edge 的 udp target 从 `e.targets.pick("udp")` 轮询取
(多个 udp target = 把 spoke 分摊到多个 tun server,= LB),再在 `e.mu` 下发布白名单(不在持锁
时调 `openChannel`)。角色沿用既有 per-pair 规则:hub 公钥更小 → 由其 `loop` 向 spoke 拨流;
更大 → 由 spoke 的 opener 入站,经现有 `serveInbound` 服务。

### 5. `p2p/direct.go` `serveInbound` —— 准入守卫(这里唯一的新职责)
守卫放在**函数最顶端、`peekTag` 之前**,同时覆盖 tagged 与 untagged 两条路径:
```go
if e.hubDenied(peer) {   // 开了 hub 模式且该 key 不在白名单
    e.log.Warn("hub peer refused", "transport", transport, "peer", keyName(peer))
    stream.Close()
    return
}
if tagged, c := peekTag(stream); tagged { /* ... 既有通道路径 ... */ }
```
放 peekTag 之前有两个理由:①**fail closed 要盖全**——只挡 tagged 分支的话,配了 tcp target
的 hub 仍允许非白名单 peer 开一条 untagged TCP 隧道进来(untagged 分支会 `bridgeInbound`),
白名单就漏了;②顺带省掉对拒绝者的 4 字节 peek。白名单内 peer 照旧:tagged 命中启动时预建的
活通道 → `serveStream`;那句瞬态的 "channel stream refused" 留给非 hub 场景。同一函数里
**未打标的入站 TCP 流**改为从 `e.targets.pick("tcp")` 轮询取目标(替代今天的单一 `e.target`,
即 LB);无 tcp target 时维持今天的拒绝语义。
`p2p/server.go` 的 `OpenTunnel`:hub 模式下 `network=="udp"` **一律拒绝**
(`codes.PermissionDenied`)——hub 独占这些通道,否则 hub 上若有 GOST 对**白名单内** peer 调
udp,`attachLocal` 的 last-dial-wins(`udp.go:130-136`)会把 dgramEdge 顶掉,静默切断该 spoke。

### 6. `p2p/config.go` + `p2p/main.go` —— 可重复 target 池 与 hub 开关

**target 池(本期就做成"多目标 + 负载均衡",对齐 k8s Service 的语义,并为未来
`--forward` 的 tcp+udp 两模式铺路)**

```go
// 每个 target 带网络语义:裸 "host:port" = tcp;显式 "udp://host:port" = udp。
type targetSpec struct{ network, addr string }
func parseTarget(v string) (targetSpec, error)

// 目标池:按网络分池;pick 轮询取一个(k8s Service 式,无健康检查)。
type targetPool struct{ byNetwork map[string][]string; rr atomic.Uint64 }
func (p *targetPool) pick(network string) (string, bool)
```

- **`--target` 可重复**;YAML 用 `targets: [...]` 列表(兼容旧 `target: <scalar>`,装载时并入
  列表)。语义与 `--forward`/`--allow` 一致:config 列表与 flag **叠加**——即
  `p2p/main.go:110-112` 今天的 `set["target"]` 覆盖逻辑要改成 append,否则 flag 会清空 config
  列表。另:`p2p/main.go:150-155` 现在用 `net.SplitHostPort(cfg.Target)` 校验,带 `udp://`
  scheme 会失败,须换成 `parseTarget`;`newEngine(..., target string)` 的第 2 参随之改为目标池。
- **按消费者取池**:未打标的入站 TCP 流 → **tcp 池**(替代今天的单一 `e.target`,每次入站
  轮询取一个 = LB);hub 的 udp 通道 → **udp 池**(每个 spoke 建通道时轮询取一个)。
- **hub 模式由存在 `--allow` 开启**;此时必须存在 ≥1 个 udp target(否则启动报错,消除歧义);
  同理无 tcp target 时入站 TCP 流按今天的"无 target 即拒"处理。
- `--allow` 可重复,每个 key 用既有 `parsePeerKey` 校验;**fail closed**:allow 列表为空、
  或 hub 模式缺 udp target → 启动报错;hub 模式同样要求 `--derp`。
- **面向未来**:`--forward` 加 UDP 时,其 datagram 侧直接复用 §2 的 `dgramEdge` 与这里的
  target 池(forward tcp ↔ tcp 池、forward udp ↔ udp 池);本轮把池与解析器一次做全,后续
  只接消费方。LB 策略先做轮询;若要 random/weighted,与 gost `selector` 的既有策略对齐即可。

## 风险 / 边界
- hub 上 per-spoke UDP fd(N+1 个);N 条 smux 会话 + 2N 个 edge goroutine——数十/数百量级
  可行,文档里写明上限。
- keepalive 时序:spoke 在 hub 静默 `ttl*3` 后重拨隧道(`client.go:84`);hub 对每个
  keepalive 都回应。`ttl` 要明显小于 NAT 空闲超时。D3 之后任何入站包都续期,只有"整条隧道
  真静默"才判死;hub 侧 `routeTTL`(=3×ttl,opt-in)必须 ≥ spoke 的重发周期,否则健康
  spoke 的路由会被误清(示例配置两侧显式写出 `ttl`)。
- keepalive 只该在"对端是 tun server"时开(D1 之后它在 p2p 链路上不再是被忽略的死配置):
  点对点链路两侧都是 client、无回显,开了会空闲重拨(详见§文档)。
- 每个 spoke 需在 hub 子网内取不同 IP(`10.10.0.<n>/24`);server 会拒绝宣告 hub 自己 IP
  的 keepalive。spoke↔spoke 无需额外配置(同源 /24 on-link → 设备 → per-peer 路由)。
  公司内网转发是 hub 内核的职责(`ip_forward` + 路由);handler 会丢弃无注册 peer 路由的
  包。
- 数据面仍为明文(白名单 + passphrase 是仅有的控制);需保密时用 WireGuard/IPsec 包裹。

bump gost 的 x pin(既有的 plugin→x→gost 链),外加 `GOWORK=off` 各项门禁。本计划止于
build/vet/test/e2e 全绿;发版是单独一步,需你另行确认。
**x 侧默认行为不变**:D1 用 `||` 保住 udp 分支的逐位行为,D2 的 routeTTL 是 opt-in(未配
`keepalive/ttl` 不过期)。因此不需要破坏性变更声明;只有显式开 `keepalive/ttl` 的部署才启用
路由过期(hub 就是这么配的)。

→ 4. `engine.go`/`udp.go` + 测试 → 5. `direct.go`/`server.go` 守卫 + 测试
→ 6. x 侧三处(`client.go` 门控 + 读取续期、`server.go` 路由过期)→ 7. 文档 → 8. e2e 脚本。

`cd p2p && CGO_ENABLED=1 go test -race ./...`;`cd x && go build ./... && go vet ./...`;
